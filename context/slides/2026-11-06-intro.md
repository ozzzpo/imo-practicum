## Слайд 32

```text
Команда
• Команда формируется, когда её участники начинают осознавать свои
  обязанности и взаимодействовать друг с другом для достижения общей
  цели

• Члены команды начинают определённым образом вести себя, вносить
  вклад в общее дело, взаимодействовать друг с другом

• У участников команды возникают определённые модели поведения и
  взаимодействия, то есть командные роли
```

## Слайд 33

```text
Функциональные роли
• Определяют конкретные задачи и обязанности, которые каждый член
  команды должен выполнять на основе своих профессиональных знаний,
  умений, навыков и опыта

• Обеспечивают необходимую экспертность для выполнения проектных
  задач — например, разработка, анализ или тестирование
```

## Слайд 35

```text
Project manager
• Зона ответственности: организация работы команды, соблюдение дедлайнов,
  коммуникация внутри команды и с преподавателем. Он следит за общей
  картиной проекта, управляет бэклогом задач и гарантирует, что команда
  движется в правильном направлении согласно техническому заданию (ТЗ)

• Ключевые навыки: организация, коммуникация, стратегическое мышление

• Вклад в проект: обеспечивает слаженность и своевременность выполнения
  работ. Представление промежуточных и итоговых результатов работы
```

## Слайд 36

```text
Data analytist
• Зона ответственности: глубокое погружение в данные. Проведение
  исследовательского анализа данных (EDA), генерация и проверка гипотез,
  инжиниринг признаков (feature engineering), интерпретация результатов
  моделей и визуализация данных. Он отвечает на вопрос «почему?» и ищет
  инсайты в данных

• Ключевые навыки: статистика, визуализация данных, критическое
  мышление, предметная область кейса

• Вклад в проект: обеспечивает, чтобы модель не была «черным ящиком», а ее
  результаты были обоснованы, понятны и несли практическую ценность
```

## Слайд 37

```text
ML-инженер
• Зона ответственности: техническая реализация ядра проекта; написание
  чистого, воспроизводимого кода для обучения моделей, создание
  пайплайнов обработки данных, настройка экспериментов.

• Отвечает за качество кода, техническую документацию ml-компоненты

• Ключевые навыки: программирование (Python, библиотеки ML), понимание
  алгоритмов

• Вклад в проект: создает работающее техническое решение, которое
  является основой всего проекта
```

## Слайд 42

```text
Scrum* — это agile-методика, с помощью которой команды могут
структурировать работу посредством коротких циклов разработки, называемых
спринтами.



*Название Scrum заимствовано из регби, где оно обозначает момент в игре,
когда участники, обхватив друг друга руками, образуют тоннель, в который
вбрасывается мяч. Команда разработки тоже объединяется, чтобы
сконцентрировать усилия на продукте
```

## Слайд 43

```text
Спринт — короткий цикл разработки, в течение которого команда стремится
создать готовый к выпуску инкремент* продукта, реализуя соответствующие
задачи




 *инкремент — совокупность всех элементов работы над продуктом, завершённых в течение спринта
```

## Слайд 44

```text
Планирование спринта
Это ключевое событие на старте каждого спринта, в ходе которого команда:
• определяет цели спринта
• выбирает задачи, которые нужно выполнить, чтобы достичь этих целей
• оценивает объём работы


Планирование спринта требует чёткого понимания приоритетов, возможностей
команды и текущих требований к продукту, чтобы обеспечить фокус на самых
важных задачах и эффективное использование ресурсов
```

## Слайд 45

```text
Ежедневные scrum-митинги
Это короткая встреча для команды разработки длительностью не более 15
минут, на которой:
• каждый участник делится тем, что было сделано с предыдущей встречи
• планируют задачи на сегодня
• обсуждают возможные препятствия на пути выполнения задач

Цели ежедневных scrum-митингов:
• поддержание прозрачности работы
• оптимизация процесса достижения целей спринта
```

## Слайд 47

```text
Обзор спринта

Проводят на вебинаре по окончании спринта. Это краткая презентация, в ходе
```

## Слайд 48

```text
Ретроспектива
Это встреча по завершении каждого спринта, на которой команда обсуждает:
• что было сделано хорошо
• что можно улучшить
• какие конкретные шаги можно предпринять, чтобы улучшить процессы в
  следующем спринте


Три главных вопроса для ретроспективы:
• Что хорошо?
• Что плохо?
• Что нужно изменить?
```
