# Проектный практикум 1 · команда 2

УрФУ и Нетология, «Проектный практикум 1», преподаватель Олег Булыгин. Команда 2 решает кейс 2 «Прогнозирование оттока абонентов телеком-оператора»: бинарная классификация, нужны вероятность ухода абонента и перечень ключевых факторов риска. Датасет — Telco Customer Churn, версия 1. Ближайшие сроки и этапы — в [требованиях курса](context/requirements.md).

## Карта репозитория

| Папка | Что там |
|---|---|
| `context/` | Материалы курса: кейс, требования, силлабус, слайды, саммари и транскрипции вебинаров, демо-ноутбук. Начинай с [карты контекста](context/README.md) |
| `docs/` | Договорённости команды: [порядок работы](docs/workflow.md), [журнал решений](docs/decisions.md) |
| `data/` | [Как получить данные](data/README.md). `data/raw/` и `data/processed/` не попадают в Git |
| `notebooks/` | EDA и эксперименты, `NN_тема.ipynb` |
| `src/` | Переиспользуемый код. Загрузка данных — `load_raw()` из `src/data.py` |
| `tests/` | Тесты кода из `src/` |
| `reports/` | Графики, отчёты, материалы защит |
| `.rulesync/` | Источник этих правил и навыков агентов |

Перед работой над данными сверь [условие кейса](context/case-02.md), перед планированием и подготовкой защиты — [требования курса](context/requirements.md).

## Источники и решения

- При расхождениях проси пользователя свериться с актуальным заданием в Нетологии. Ссылайся на карточку занятия, слайд или таймкод. Автоматические транскрипции служат источником фактов, но могут содержать ошибки распознавания. Подробно — навык `checking-course-requirements`.
- Решения команды о данных, метриках, разбиении выборки и ролях записывай в [журнал решений](docs/decisions.md). Различай договорённости команды и требования преподавателя. Подробно — навык `recording-decisions`.
- Ставь решению статус «принято», только если пользователь подтвердил, что команда его согласовала. Своё предложение записывай как «предложено».

## ИИ и авторство

Силлабус разрешает ИИ, если участник сам проверяет результат и **сам делает выводы по ключевым пунктам** ([силлабус](context/syllabus.md#использование-ии-при-выполнении-заданий)). Поэтому:

- считай, строй графики, ищи ошибки и предлагай гипотезы;
- формулировки выводов для ноутбуков и защит помечай как черновик для участника, например `> Черновик ИИ — проверить и переписать`;
- не выдавай гипотезу за установленный факт и называй данные, на которых она основана.

## Данные и код

- Окружение ведёт uv: Python 3.12, зависимости в `pyproject.toml`, точные версии в `uv.lock`. Код запускай через `uv run`. Библиотеку добавляй только через `uv add` (`uv add --dev` для инструментов), не через `pip install`, и коммить `pyproject.toml` и `uv.lock` вместе с кодом, который её использует.
- Данные читай только через `load_raw()`. Данные, `.env` и секреты не коммить.
- Обработку, которую повторяют несколько ноутбуков, выноси в `src/` с тестом в `tests/`.
- Статистики для заполнения пропусков, масштабирования и кодирования считай только на обучающей части после разбиения, внутри `Pipeline`. Иначе тестовая часть утечёт в обучение.
- Ноутбуки коммить после Restart & Run All, вместе с выводами ячеек. Тяжёлые HTML-отчёты сохраняй в `reports/`.

## Git

- `main` всегда рабочий. Работа идёт в ветке `<фамилия>/<кратко>`, в `main` попадает через PR с ревью участника.
- Перед PR запускай `uv run pytest`.
- Не правь сгенерированные файлы: `CLAUDE.md`, `AGENTS.md`, `.claude/skills/`, `.agents/skills/`, `.opencode/skills/`. Меняй источник в `.rulesync/` и перегенерируй. Источник и результат коммить вместе.

Полные правила — в [docs/workflow.md](docs/workflow.md).

## Навыки

| Навык | Когда применять |
|---|---|
| `doing-eda` | Разведочный анализ Telco: что проверить, известные особенности данных, как оформить ноутбук и выводы |
| `recording-decisions` | Запись или изменение решения команды в `docs/decisions.md`, разделение договорённостей и требований |
| `checking-course-requirements` | Вопросы о сроках, заданиях, защитах и оценивании, сверка с материалами курса |
| `managing-agent-rules` | Изменение правил или навыков агентов, перегенерация `CLAUDE.md` и `AGENTS.md` |

## Команды

```bash
uv sync                                   # окружение строго по uv.lock
uv run pytest                             # тесты, тест реального CSV пропускается без данных
uv run jupyter lab                        # ноутбуки
uv add <пакет>                            # новая зависимость (--dev для инструментов)
npx --yes rulesync@16.24.0 generate       # перегенерировать правила агентов
npx --yes rulesync@16.24.0 generate --check   # проверить, что они актуальны
```
