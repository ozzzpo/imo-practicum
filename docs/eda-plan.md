# План первичного EDA Telco Customer Churn

Дата составления: 2026-11-07.  
Срок: к занятию 2026-11-13 по исходному расписанию курса.

Основание: [условие кейса](../context/case-02.md), [требования к EDA](../context/requirements.md#ожидания-от-eda), [описание данных](../data/README.md), [саммари вебинара](../context/summaries/2026-11-06-eda.md) и [демонстрационный ноутбук Spotify](../context/notebooks/eda_spotify.ipynb.ipynb).

## Цель

Определить, какие характеристики абонентов, подключённые услуги, условия договора и платежи связаны с оттоком `Churn`. Подготовить обоснованные гипотезы о факторах риска и преобразованиях данных для последующего моделирования. Связь признака с оттоком не интерпретировать как доказательство причинности.

## Этапы

1. **Загрузить и описать данные.**
   Проверить размер таблицы, первые и случайные строки, типы и смысл полей с помощью `head()`, `sample()`, `info()` и `describe()`. Убедиться, что одна строка соответствует одному абоненту.

2. **Проверить качество данных.**
   Найти полные дубликаты, повторы `customerID`, пропуски, скрытые пропуски и недопустимые значения. Преобразовать `TotalCharges` в числовой тип и отдельно исследовать 11 пробельных значений при `tenure = 0`. Способ их обработки выбрать после анализа и обосновать, не удаляя строки автоматически.

3. **Проанализировать целевую переменную.**
   Построить распределение `Churn`, рассчитать количество и долю классов. Зафиксировать исходный дисбаланс: 26,5% ушедших и 73,5% оставшихся абонентов.

4. **Выполнить одномерный анализ признаков.**
   Для `tenure`, `MonthlyCharges` и `TotalCharges` построить гистограммы и boxplot, рассчитать медианы и квартили. Для категориальных признаков рассчитать частоты и построить столбчатые диаграммы. Выбросы исследовать с учётом смысла данных, не удаляя их только по правилу IQR.

5. **Сравнить группы оттока.**
   Сравнить числовые признаки между `Churn = Yes` и `Churn = No` с помощью boxplot или violinplot и таблицы медиан. Для категориальных признаков рассчитать долю оттока внутри каждой категории и размер группы. Приоритетно рассмотреть `Contract`, `InternetService`, `TechSupport`, `OnlineSecurity`, `PaymentMethod`, `Partner` и `Dependents`.

6. **Исследовать связи между признаками.**
   Построить диаграммы рассеяния для ключевых числовых пар и матрицу φk для смешанных типов данных. Для числовых признаков дополнительно рассмотреть корреляции Spearman и Pearson. Проверить мультиколлинеарность, особенно между сроком обслуживания и начислениями. Исключить `customerID` из корреляционного анализа.

7. **Сформулировать выводы и гипотезы.**
   Собрать потенциальные факторы риска, ограничения выборки и решения по очистке данных. Каждый вывод подкрепить графиком или таблицей и оформить итоговую последовательность «наблюдение → решение → гипотеза для модели».

## Результат

- Воспроизводимый ноутбук команды в `notebooks/` с графиками и краткими выводами после каждого блока.
- Итоговая таблица наблюдений, решений по данным и гипотез для моделирования.
- Отдельно зафиксированные спорные решения и ограничения анализа.

`ydata-profiling` использовать дополнительно для самопроверки. Дашборд Streamlit и radar chart в обязательный объём первичного EDA не входят. Бейзлайн строить после следующего занятия согласно требованиям курса.
