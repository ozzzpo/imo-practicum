# Порядок работы

Правила команды по коду, данным и Git. Это договорённости команды, а не требования преподавателя. Требования курса собраны в [context/requirements.md](../context/requirements.md). Принятые решения записываются в [журнал](decisions.md).

## Окружение

Окружение ведёт [uv](https://docs.astral.sh/uv/). Python 3.12 закреплён в `.python-version`, зависимости — в `pyproject.toml`, точные версии всех пакетов — в `uv.lock`. Установка описана в [README](../README.md#быстрый-старт).

- После `git pull` выполни `uv sync`, чтобы окружение совпало с `uv.lock`.
- Новую библиотеку ставь через `uv add <пакет>`, инструмент только для разработки — через `uv add --dev <пакет>`. `pyproject.toml` и `uv.lock` коммить в том же PR, где библиотека начинает использоваться.
- `uv.lock` руками не правь и `pip install` в `.venv` не используй: такие изменения не попадут к остальным.
- В Colab uv не нужен. Недостающее ставь в ячейке, например `!pip install phik`.

## Данные

- Исходный CSV лежит в `data/raw/` и в Git не попадает. Как скачать — в [data/README.md](../data/README.md).
- Ноутбуки и код читают данные только через `load_raw()` из [src/data.py](../src/data.py). Функция сверяет SHA-256, поэтому у всех одна и та же таблица.
- Обработка, которую повторяют несколько ноутбуков, переносится в `src/` и покрывается тестом в `tests/`.
- Подготовленные наборы сохраняются в `data/processed/`, в `data/README.md` описывается, каким кодом они получены.

## Ноутбуки

- Имя начинается с номера этапа: `01_eda.ipynb`, `02_baseline.ipynb`. Черновики участника — с фамилией в имени, например `01_eda_tyurin.ipynb`.
- Подключение кода проекта в первой ячейке:

  ```python
  import sys; sys.path.append("..")
  from src.data import load_raw
  ```

- Перед коммитом выполни Restart & Run All. Выводы оставляем: преподаватель смотрит код с графиками. Отчёты ydata-profiling и другие тяжёлые HTML сохраняй в `reports/`, а не в выводы ячеек.
- Каждый вывод в ноутбуке пишется текстом в Markdown-ячейке под графиком. Выводы по ключевым пунктам команда делает сама, это условие использования ИИ из [силлабуса](../context/syllabus.md#использование-ии-при-выполнении-заданий).

## Git

- `main` всегда рабочий. На задачу — ветка `<фамилия>/<кратко>`, например `tyurin/eda-target`.
- В `main` попадают только через PR, перед слиянием PR смотрит ещё один участник.
- Перед PR запусти тесты: `uv run pytest`.
- В коммит не попадают данные, `.venv` и секреты. Это закрывает [.gitignore](../.gitignore).

## Правила для ИИ-агентов

Правила и навыки агентов пишутся в `.rulesync/`, а [rulesync](https://github.com/dyoshikawa/rulesync) генерирует из них `CLAUDE.md`, `AGENTS.md` и навыки для Claude Code, Codex CLI и OpenCode. Сгенерированные файлы руками не правь: CI сравнивает их с источником и падает при расхождении.

Чтобы изменить правило, поправь `.rulesync/rules/00-practicum.md` или навык в `.rulesync/skills/`, затем выполни команду ниже. Нужен Node.js.

```bash
npx --yes rulesync@16.24.0 generate
```

Источник и сгенерированные файлы коммить вместе. Личные дополнения клади в `.rulesync.local/`, эта папка в Git не попадает. Подробности — в навыке [managing-agent-rules](../.rulesync/skills/managing-agent-rules/SKILL.md).
